# 本地文件多标记交叉管理系统 V1.2 需求设计文档 (PRD)

## 1. 项目背景

### 1.1 版本回顾

V1.0 完成了核心基础建设：文件导入、SHA256 哈希去重、多级标签树、软删除机制、MVVM 分层架构、图片和文本文件预览。

V1.1 完成了交互范式重构：全局命令面板（Ctrl+K）、智能侧边栏动态计数、右侧 Inspector 面板就地编辑标签，大幅提升了操作效率和数据量级感知。

### 1.2 问题现状

当前系统存在三个严重的数据一致性隐患和功能缺口：

1. **文件系统与数据库脱节**：用户通过资源管理器（Explorer/Finder）移动、重命名或删除文件后，数据库中的 `full_path` 变成死链，所有已投入的标签劳动随即失效。这是元凶级问题——用户对系统"打标-检索-复用"工作流的信任将因路径断裂而瓦解。

2. **搜索历史未落地**：`search_history` 表在 V1.0 schema 中已建好，但 `search_files()` 从未写入过数据。命令面板无法通过 ↑ 键回溯历史。

3. **全文搜索未实现**：用户只能按文件名和扩展名搜索，无法搜索文件内容。此功能推迟至 V1.3。

### 1.3 V1.2 目标

- **P0（首要核心）**：集成 watchdog 实现本地文件实时监控，保证数据库路径与物理文件实时同步，保护 V1.1 用户已投入的标签劳动。
- **P1（顺手完成）**：补全 search_history 写入逻辑，并在命令面板中支持箭头键调取最近搜索历史。
- **P2（明确延后）**：全文搜索（FTS）推迟至 V1.3，本版本不做。

### 3.2 与 ViewModel 的解耦方式

`FileMonitor` 服务不直接引用 ViewModel，通过 PyQt5 Signal 通信：

```
┌─────────────┐     events     ┌───────────────┐     signals      ┌──────────┐
│   watchdog   │ ─────────────> │ FileMonitor   │ ─────────────> │   VM +   │
│  Observer    │   callback     │ (Service)     │ pyqtSignal     │   View   │
└─────────────┘                └───────────────┘                └──────────┘
```

- `FileMonitor` 内部维护一个 `QTimer` 驱动的 debounce 队列（而非 threading.Timer），天然与 Qt 事件循环集成。
- 事件处理回调仅将变更推入队列，不执行 SQL。
- Debounce 超时后触发 `file_system_changed` 信号，由 `MainViewModel` 订阅并执行数据库更新。
- ViewModel 更新完成后发出 `files_updated` 信号驱动 UI 刷新。

### 3.3 数据流

```
用户操作本地文件 (Explorer)
        │
        ▼
watchdog 底层 API (OS 原生)
        │
        ▼ (回调)
FileMonitor._on_event(event)
        │
        ▼ (入队)
Debounce Queue (dict[file_hash, EventType])
        │
        ▼ (QTimer 超时, 主线程)
FileMonitor._flush()
        │ emit file_system_changed(batch: list[FileEvent])
        ▼
MainViewModel._on_file_system_changed(batch)
        │ (逐一匹配 file_hash, 执行 SQL)
        │ emit files_updated / tags_updated
        ▼
UI 组件刷新
```

### 3.4 QTimer 集成方案

`FileMonitor` 继承 `QObject`，内部持有 `QTimer`：

```python
class FileMonitor(QObject):
    file_system_changed = pyqtSignal(object)  # list[FileEvent]

    def __init__(self, debounce_ms=2000, parent=None):
        super().__init__(parent)
        self._debounce_ms = debounce_ms
        self._pending: dict[str, FileEvent] = {}  # file_hash -> event
        self._timer = QTimer(self)
        self._timer.setSingleShot(True)
        self._timer.timeout.connect(self._flush)
        self._observer = Observer()
```

关键点：
- `_on_event` 回调将事件写入 `_pending` 字典并重启 `_timer`。
- `_flush` 在主线程执行，遍历 `_pending` 字典发出 `file_system_changed`，然后清空字典。
- 不需要 `QMetaObject.invokeMethod` 或自定义跨线程传输——watchdog 默认在新线程回调，但 `_on_event` 只做字典操作（线程安全，GIL 保护），`_flush` 由 `QTimer` 在主线程触发。

### 3.5 监控目录管理

- `FileMonitor` 接收一个目录列表 `watch_dirs: list[Path]` 指定要监控的父目录。
- 启动时（`start()`）为每个目录添加 watchdog 的 `RecursiveHandler`。
- 通过 watchdog 的 `PatternMatchingEventHandler` 过滤非目标文件（如临时文件 `*.tmp`、`~$*` 等）。

## 6. 数据结构变更

### 6.1 Schema 变更决策：不增加 inode 字段

经过分析，**V1.2 不需要修改数据库 Schema**。理由如下：

- **inode 的跨平台问题**：Windows 使用 `FileIndex`（卷相关、非稳定），macOS 和 Linux 的 inode 在文件移动/复制后也经常变化。依赖 inode 作稳定标识反而会增加维护复杂度和跨平台 bug。
- **已有稳定标识**：`files.file_hash`（SHA256）已经是内容级稳定标识。文件移动/重命名不改变内容，因此 hash 不变；文件修改会改变 hash，但新旧文件应视为不同版本（或提示用户）。
- **唯一的极端场景**：空文件（零字节）的 SHA256 都是 `e3b0c442...` 相同；同一内容复制到多个位置会共享同一 hash——但这恰是设计的正确行为（文件去重）。
- **hash 计算的代价**：watchdog 场景下不需要为每个事件重新计算 hash。对于 moved/renamed 事件，路径已知，可以直接通过文件大小 + 文件名 + 目录 辅助匹配作为 fallback；对于 deleted 事件，已无法计算 hash，需要额外策略（见下文）。

**结论**：保持现有 `files` 表结构不变，依靠 file_hash（有索引）作为文件标识。

### 6.2 已删除文件的 fallback 匹配策略

对于 `deleted` 事件，文件已不存在于磁盘，无法计算 SHA256。为此采用**三元组匹配**作为 fallback：

```python
def _match_deleted_file(self, full_path: str, file_size: int) -> Optional[int]:
    """尝试通过路径+大小匹配已删除文件（文件已消失，无法计算 hash）"""
    with self._db.connect() as conn:
        row = conn.execute(
            """
            SELECT id FROM files
            WHERE full_path = ? AND file_size = ? AND is_deleted = 0
            LIMIT 1
            """,
            (full_path, file_size),
        ).fetchone()
    return row["id"] if row else None
```

对于 `moved` 事件，目标路径已知，可以重新计算 hash 精确匹配——但文件可能很大。优化方案：先用 `file_size + file_name` 在数据库中预筛选，缩小可能匹配的范围，避免对每个 moved 事件都做全量 hash 计算。

## 7. 技术选型

### 7.1 watchdog 适配策略

| 平台 | watchdog 后端 | 特点 | 注意事项 |
|------|---------------|------|----------|
| Windows | `ReadDirectoryChangesW`（通过 `pywatchman` 封装） | 原生 API，支持递归监控，事件丰富 | FileAttributesModified 噪声多，需过滤 |
| macOS | `FSEvents` | 支持递归，可获取事件时间戳 | macOS 10.15+ 需要权限授权 |
| Linux | `inotify` | 最稳定，事件粒度细 | /proc/sys/fs/inotify 限制监控数量 |

watchdog 的 `Observer` 会自动选择当前平台的最佳后端，开发者只需关注事件处理逻辑。

### 7.2 关键事件过滤

```python
class FileChangeHandler(PatternMatchingEventHandler):
    # 忽略的临时文件模式
    IGNORE_PATTERNS = ["*.tmp", "*.temp", "~$*", "*.swp", "*.swx", "*.lnk", "Thumbs.db"]
    # 忽略的目录
    IGNORE_DIRS = [".git", "__pycache__", ".DS_Store"]
    
    def on_modified(self, event):
        if not event.is_directory:
            self._queue_event("modified", src_path=event.src_path)
    
    def on_created(self, event):
        if not event.is_directory:
            self._queue_event("created", src_path=event.src_path)
    
    def on_deleted(self, event):
        if not event.is_directory:
            self._queue_event("deleted", src_path=event.src_path)
    
    def on_moved(self, event):
        if not event.is_directory:
            self._queue_event("moved", src_path=event.src_path, dest_path=event.dest_path)
```

```python
        qtbot.addWidget(m)  # 确保 QObject 被 Qt 管理
        yield m
        m.stop()
    
    def test_start_stop(self, monitor, tmp_path):
        """FileMonitor 启动和停止不影响主线程"""
        monitor.start([tmp_path])
        assert monitor.is_running()
        monitor.stop()
        assert not monitor.is_running()
    
    def test_debounce_merges_events(self, monitor, tmp_path, qtbot):
        """同一文件的多次修改在 debounce 窗口内合并"""
        events: list[list[FileEvent]] = []
        monitor.file_system_changed.connect(events.append)
        
        monitor.start([tmp_path])
        
        test_file = tmp_path / "test.txt"
        test_file.write_text("v1")
        test_file.write_text("v2")  # 同一文件两次修改
        
        # 等待 debounce 触发
        def check():
            if len(events) > 0:
                return True
            return False
        
        qtbot.waitUntil(check, timeout=5000)
        monitor.stop()
        
        # 应该只有一个批次，且仅包含一个 modified 事件
        assert len(events) == 1
        assert len(events[0]) == 1
        assert events[0][0].event_type == "modified"
    
    def test_moved_event_detected(self, monitor, tmp_path, qtbot):
        """文件移动/重命名检测"""
        events: list[list[FileEvent]] = []
        monitor.file_system_changed.connect(events.append)
        
        src = tmp_path / "old_name.txt"
        src.write_text("hello")
        dst = tmp_path / "new_name.txt"
        
        monitor.start([tmp_path])
        src.rename(dst)
        
        def check():
            if len(events) > 0:
                return True
            return False
        
        qtbot.waitUntil(check, timeout=5000)
        monitor.stop()
        
        assert len(events) >= 1
        moved = [e for batch in events for e in batch if e.event_type == "moved"]
        assert len(moved) >= 1
        assert moved[0].dest_path == str(dst.resolve())
```

## 10. 风险评估

| 风险 | 可能性 | 影响 | 应对策略 |
|------|--------|------|----------|
| watchdog 在 Windows 上产生大量 FileAttributesModified 噪声 | 高 | 中 | 使用 `PatternMatchingEventHandler` 过滤；在 handler 中跳过纯元数据变更（仅文件大小和最后修改时间变化才入队） |
| 用户同时操作大量文件（如 `git clone`）导致事件风暴 | 中 | 中 | debounce 窗口内合并同一文件事件；设置队列最大长度上限（如 10000），超出时强制 flush |
| 文件在计算 hash 过程中被删除/移动 | 低 | 高 | 在 handler 中捕获所有 OSError；deleted 事件不计算 hash，使用 fallback 匹配；moved 事件以目标路径为准重新匹配 |
| 监控的 USB 磁盘被弹出 | 低 | 中 | watcher 抛出 `OSError`（`FileNotFoundError`）时，自动停止对应目录的监控并记录日志，不崩溃 |
| macOS 权限提示 | 中 | 低 | 启动时检查目录可访问性，若因权限被拒则友好提示用户 |
| search_history 表增长失控 | 低 | 低 | 每次写入后检查总条数，超出 50 条时删除最早记录（O(1) 通过 id 对比） |

## 11. 向下兼容说明
