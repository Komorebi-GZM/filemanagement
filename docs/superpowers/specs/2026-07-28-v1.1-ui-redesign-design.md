# 本地文件多标记交叉管理系统 V1.1 需求设计文档 (PRD)

## 1. 目标与背景
V1.0.0 实现了本地文件多标签管理的基础架构（PyQt5 + SQLite），验证了文件拖拽打标、元数据隔离等核心机制。但在高频使用场景下，“拖拽”操作链路较长，且传统的三栏式布局对空间利用率不足。
V1.1 的核心目标是：**重构交互链路，引入极客风格的全局命令面板 (Command Palette)**，并**全面现代化 UI 布局**，提升数据量感知和操作的无缝衔接。

## 2. 核心交互重构：全局命令面板 (Command Palette)
将 `Ctrl + K` 悬浮命令面板作为系统的操作中枢，接管高频的“打标签”与“全局搜索”动作。

### 2.1 唤醒与响应机制
- **快捷键**：全局侦听 `Ctrl + K` 唤起居中高斯模糊的悬浮输入框，`Esc` 键随时退出/取消。
- **上下文感知**：
  - **已选中文件时**：面板处于“打标模式”，用于为当前选中的文件批量添加/移除标签。
  - **未选中任何文件时**：面板处于“全局搜索模式”，用于跨库搜索文件名或特定标签。

### 2.2 打标签操作流程
- **实时模糊匹配**：输入标签名时，下拉列表实时推荐现有标签（支持拼音、首字母和子串匹配）。
- **Tab 键补全**：输入部分字符后，按 `Tab` 键自动补全高亮推荐的标签全名。
- **一键新建**：若输入的字符无匹配项，下拉列表第一项变为 `创建新标签：[文本]`，回车即创建并生效。
- **语法拓展**：支持指令前缀，例如直接输入 `设计` 为添加标签，输入 `-设计` 并在下拉中回车，则表示移除该标签。

## 3. 前端界面与布局优化 (UI Redesign)
摒弃“以标签树为核心”的重度侧边栏，转向“以内容过滤为核心”的现代化布局。

### 3.1 左侧栏：智能导航 (Smart Sidebar)
- **极简结构**：收起臃肿的全量标签树，改为“按需展开”。
- **智能视图**：固定展示“全部文件”、“最近导入”、“未打标文件”等智能视图，以及用户自定义的“固定/常用标签”。
- **动态计数器**：每个智能视图和固定标签右侧，**实时显示当前条件下的文件数量**（如“全部文件 12,384”），让用户在点击前即可建立数据量级预期。

### 3.2 主内容区：多视图模式 (Main Content)
- **空间释放**：左侧栏折叠后释放大量空间，文件列表区域扩大。
- **多视图切换**：
  - **列表视图 (List View)**：保留原有的高性能数据网格，适合办公文档，展示详细元数据。
  - **画廊视图 (Gallery View)**：新增网格化缩略图视图，利用已有的图像预览能力，极大提升素材、图片类文件的管理体验。

### 3.3 右侧栏：整合式详情卡片 (Inspector Panel)
- **纵向流式排版**：选中文件后，右侧滑出统一卡片，自上而下依次为：高清预览区 -> 标签管理区 -> 文档简介 -> 文件印记。通过上下滚动即可查阅，取消原有的 Tab 切换逻辑。
- **就地编辑 (In-place Edit) 与无缝衔接**：
  - **移除标签**：标签区展示为胶囊 (Pill)，点击胶囊上的 `×` 直接移除，无需确认。
  - **添加标签**：点击标签区底部的 `+` 按钮，将自动唤醒 `Ctrl + K` 命令面板，并自动将目标作用域锁定为当前文件，实现“鼠标点击触发，键盘丝滑输入”的无缝结合。

## 4. 技术与性能约束
- **搜索性能**：Command Palette 的实时模糊匹配要求极速响应，前端需引入内存缓存 (Trie 树或简单字典) 或优化 SQLite LIKE 查询，确保输入延迟低于 50ms。
- **动态计数更新**：左侧边栏的计数器在文件发生增删、标签变更时需要实时刷新。需确保计数 SQL 的高效性（可考虑数据库触发器更新缓存表或防抖更新策略），避免引发全局 UI 卡顿。
- **向下兼容**：V1.1 的数据库表结构与 V1.0 完全兼容，UI 的重构主要发生在 `MainViewModel` 的逻辑调整和 `MainWindow` 视图组件的重写上。
